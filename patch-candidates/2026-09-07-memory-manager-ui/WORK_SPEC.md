# 메모리 관리 UI 개편 — 메인앱 반영 명세

## 적용 범위
- 작업: 기존 저장 메모리 관리 화면 개편. 웹 관리 컴포넌트 수정 + 코어 일괄 관리 API 추가.
- 진입점: 기존 메모리 관리 열기 이벤트/메뉴 유지.
- 데이터: 기존 UserMemoryStore의 global / project / session 항목. 신규 비밀키나 외부 서비스 없음.
- 사용자 메모리 파일, 배포 패키지, 실행 중인 메인앱에는 직접 변경하지 않음.
- 상태: 개발 소스 적용 및 격리 회귀 검증 완료. 메인앱 배포/실행 중 앱에서의 통합 검증은 별도.

## 구현 내역
1. 넓은 범위 탐색 / 요약 목록 / 상세 편집 레이아웃. 좁은 화면은 목록과 상세를 전환.
2. 항상 표시되는 본문 검색, 범위·활성 상태·등록 방식 필터, 수정 최신/오래된 순·생성순·본문순 정렬.
3. 30개 단위 클라이언트 페이지 표시. 서버 전체 조회와 범위별 100개 저장 한도는 그대로 유지.
4. 명시적인 저장·취소, 다중행 편집(500자), 포커스 이탈 자동 저장 제거. 미저장 변경 폐기 확인.
5. 체크박스는 활성 스위치가 아니라 일괄 작업 선택. 현재 페이지 전체 선택, 페이지 밖 선택 개수, 필터 변경 시 선택 초기화.
6. 선택 항목 활성/비활성·범위 이동·삭제. 작업마다 영향 범위 확인. 삭제는 확인 후 영구 삭제이며 되돌리기 기능은 없음.
7. 이동 시 기존 ID·생성일·활성 상태·등록 방식 유지. 대상의 중복·용량 및 선택 항목 유효성을 전부 검증한 뒤 한 번 저장. 검증 실패 시 일부 항목만 처리하지 않음.
8. 본문 정규화(공백/대소문자) 기준 동일 내용 경고 및 UI 저장 차단. 이동 API에서도 중복 차단. 의미상 충돌 분석이 아님.
9. 로딩/오류/빈 결과 구분, 쓰기 실패 시 편집 초안 보존, 재시도, 창 재열기 후 이전 조회 결과 무시. 열린 상태에서 다른 열기 이벤트로 초안이나 작업 대상을 덮어쓰지 않음.
10. 활성 상태는 저장 범위 전체에 영향을 주며 챗별 제외나 실제 응답 전달 내역이 아니라는 안내.
11. 개발 서버의 메모리 API 프록시 누락 보완.

## 변경 단위 / 반영 대상
- UserMemoryPanel.tsx: 기존 관리 화면 교체. 기존 openUserMemoryPanel / UserMemoryPanelHost 공개 진입점 유지.
- myAgentClient.ts: batchUserMemory 클라이언트 추가.
- vite.config.ts: /memory 프록시 추가.
- core/src/memory/user-memory-store.ts: MemoryBatchInput 및 batch 추가.
- core/src/routes/dispatch.ts: POST /memory/batch 연결. 기존 단일 항목 CRUD 유지.
- tools/verify-memory-manager.mjs: 임시 저장소 회귀.
- tools/verify-memory-manager-ui.mjs: 실제 관리 컴포넌트 + 확인 모달의 격리 Chromium 회귀.

코어와 UI 변경은 함께 반영해야 한다. UI만 배포하면 일괄 작업 API를 사용할 수 없다. 기존 관련 변경은 덮어쓰지 말고 해당 변경 단위만 병합한다.

## API 계약
POST /memory/batch
- ids: 비어 있지 않은 문자열 배열, 최대 300개. 동일 ID는 한 번 처리.
- action: enable / disable / delete / move.
- project_id / session_id: 현재 관리 맥락. 선택한 project/session 항목이 그 범위에 속하는지 검증.
- target_scope: move일 때 global / project / session. 현재 맥락에서 사용 가능한 대상만 허용.
- 성공: { changed: number }.
- 오류: INVALID_BATCH / STALE_SELECTION / INVALID_TARGET / SCOPE_FULL / DUPLICATE_TEXT, HTTP 400.
- 이 맥락 검사는 기존 로컬 API 모델의 오조작 방지이며 다중 사용자 권한 시스템을 새로 구현한 것은 아니다.
- 저장 전 전체 검증의 원자성을 제공한다. 기존 JSON 파일 저장 방식 자체의 장애 복구/다중 프로세스 트랜잭션은 변경하지 않았다.

## 이번에 구현하지 않은 기능
아래 항목을 구현 완료로 취급하거나 비활성 가짜 버튼으로 노출하지 않는다.
- 응답 우클릭 요청/응답 페어 추출 및 챗 배경 대화 추출, 모델 후보 승인 화면.
- 추출 출처 저장·원본 대화 이동. 기존 데이터에는 출처가 없어 ‘기록 없음’으로 표시.
- 프로젝트와 작업폴더의 독립 스키마 및 두 범위 동시 조회. 현재 UI는 기존 project 범위를 ‘프로젝트 / 작업폴더’로 표시하며 현재 소속 노드 하나만 조회한다.
- 챗별/요청별 사용 제외, 기억 사용과 후보 제안 설정 분리, 실제 전달 메모리 내역.
- 의미상 중복·충돌 검토, 모든 프로젝트를 가로지르는 검색/이동.
- 기존 문구 감지 자동 축적 및 프롬프트 주입 정책 변경.
- 서버 페이지 조회, 100개/범위 한도 확대, 가상 스크롤.

## 검증
- 코어 TypeScript 컴파일: 통과.
- 관리 UI TypeScript 컴파일: 통과.
- `node tools/verify-memory-manager.mjs`: 통과. 범위 이탈·잘못된/누락 ID·잘못된 작업·목적지 누락·중복·용량 초과 시 디스크 무변경, 이동 상태/ID/생성일 보존, 다중 활성/비활성/삭제, 재조회 지속성 검증.
- `node tools/verify-memory-manager-ui.mjs`: 통과. 실제 컴포넌트로 66개 목록 페이지/검색/필터/정렬, 포커스 이탈 비저장, 저장 실패 후 초안과 재시도, 범위 이동 및 비활성 보존, 삭제 취소/승인, 중복 차단, 미저장 종료 취소, 좁은 화면 상세, 조회 오류 복구, 지연 응답 격리 검증.
- 브라우저 테스트는 임시 저장소를 사용하는 네트워크 인터셉트로 API에 응답한다. 운영 API 디스패처 전체나 실제 실행 중 메인앱의 end-to-end 검증은 아니다.
- 실제 사용자 저장소나 메인앱 서버에 테스트 데이터를 넣지 않았다. 임시 서버·브라우저·테스트 저장소는 종료/정리한다.

## 후속 전체 기능 수용 기준
수동 추출 기능은 출처/범위 스키마와 함께 구현하여 요청·응답 연결, 승인 전 비저장, 취소, 중복 후보, 민감 정보 제외, 긴 대화 분석 범위 안내를 검증해야 한다. 챗별 적용 제외는 저장 원본 활성 상태와 별도로 구현해야 한다.
