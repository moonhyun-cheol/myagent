# 첨부 이미지 상호작용 및 대화 참조 보관

## 적용 범위
- 전송 대기 이미지: 버튼/키보드 접근, 크게 보기, 우클릭 크게 보기·주소 복사·이미지 복사·저장. 제거 버튼과 분리.
- 전송 후 사용자 메시지: 디스크 첨부 URL을 이미지 표시 및 기존 이미지 상호작용에 연결. blob URL은 전송 시 폐기하고 지속 URL 사용.
- 사용자 메시지 저장: 네 요청 저장 경로에서 서버가 세션 소유 첨부를 조회하여 id/name/mime/url을 기록. 없는 ID는 제외하고 중복 ID 제거. 절대 경로와 이미지 바이트를 메시지 JSON에 넣지 않음.
- 다시 열기: 저장된 첨부 메타데이터로 이름 및 이미지 URL 복원.
- 이전 대화: 세션별 첨부 목록 API와 접이식 '대화 첨부 이미지 보기' 제공. 디스크에 남은 옛 첨부를 조회하되 특정 메시지에 임의 매칭하지 않음. 전송 대기 파일도 포함될 수 있음을 안내.
- 갤러리: 로딩/빈 상태/실패 및 새로고침 재시도, 세션 전환 시 컴포넌트 초기화와 진행 조회 취소, lazy 이미지 표시.
- 정리 작업: 메시지 첨부 참조를 공유 파일 보존 판단에 포함.

## 보관 정책 및 한계
원본은 기존 세션별 첨부 디렉터리에 유지하고 메시지는 참조만 보관한다. 앱 재시작에 영향받지 않는다. 원본 파일이 이미 삭제된 과거 이미지를 복구하지는 않는다. 현재 챗 삭제 시 전용 파일을 정리하고 다른 대화가 참조한 파일은 보존하는 기존 정책을 유지한다.

현재 세션 메시지는 최근 80개 보관 제한이 있다. 이번 수정은 무제한 대화 보관/아카이브 구현이 아니다. 잘린 메시지의 이미지도 세션 파일 목록에서 남은 파일을 확인할 수 있지만, 원래 요청·응답 페어를 완전하게 장기 보존한다고 보장하지 않는다. 대화 JSON 내보내기만으로 원본 이미지가 다른 PC로 이동하지 않는다.

장기 보관 후속 설계: 모델 입력용 최근 메시지와 사용자 열람용 전체 대화 아카이브를 분리하고, 안정된 메시지 ID 및 첨부 manifest로 연결한다. 파일 크기·해시·원본명·MIME·생성 시각을 보존하며, archive를 포함한 참조 수로 삭제를 판단한다. 내보내기는 대화 JSON+manifest+원본 파일을 패키징하고 가져오기 시 참조를 새 세션으로 재작성한다. 용량 정책은 사용자에게 고지하고 명시적 삭제/내보내기를 제공하며, 오래된 파일을 조용히 지우지 않는다. 기존 80개 이전에 삭제된 메시지는 복원 불가를 명시한다.

## 검증
- 코어 TypeScript 컴파일 통과.
- UI TypeScript 컴파일 통과.
- tools/verify-chat-attachments.mjs 통과: 세션 소유권, 중복/없는 첨부, 경로 입력 거절, 메시지 디스크 재로딩, AttachmentService 재생성 후 동일 바이트 조회, 세션 목록, GC 참조/원본 유지, 옛 파일 조회와 잘못된 메시지 배정 방지, 네 요청 경로 연결.
- tools/verify-session-temp-gc.mjs 기존 회귀 통과.
- 사용자 데이터는 테스트하지 않음. 임시 격리 디렉터리 사용 후 정리.
- 실제 앱 E2E 및 운영 클립보드 권한, 배포 검증은 미실시. 메인앱 배포는 수행하지 않음.

## 메인앱 반영
첨부 서비스/세션 타입/요청 저장/정리 참조/API의 코어 변경과 클라이언트 타입/메시지 복원/첨부 버튼/새 세션 첨부 갤러리 변경을 함께 반영한다. 코어와 UI를 함께 빌드해야 하며 기존 JSON은 선택 필드가 없어도 그대로 읽는다. 승인 전 운영 데이터 마이그레이션이나 자동 삭제를 실행하지 않는다.
