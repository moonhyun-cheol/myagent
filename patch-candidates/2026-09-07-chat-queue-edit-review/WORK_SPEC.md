# 채팅 큐 편집 및 검토 후 진행 작업명세서

## 목적

실행 중인 채팅에 추가된 후속 메시지를 큐에서 직접 수정할 수 있게 하고, 두 개 이상의 메시지가 대기 중인 경우 현재 작업 완료 직후 자동으로 다음 메시지를 실행하지 않도록 한다. 사용자가 모든 큐 내용을 확인·편집한 뒤 명시적으로 진행하면 원래 FIFO 순서대로 실행한다.

## 변경 파일

- `ui/workspace/src/store/workspaceStore.ts`
- `ui/workspace/src/components/ChatPane.tsx`

## 구현 내용

### 큐 상태 및 동작

- `updateQueuedMessage(id, text)`를 추가해 큐 항목의 위치와 메타데이터는 그대로 유지하면서 텍스트만 저장한다.
- `queueReviewSessions`로 현재 작업 완료 후 사용자 검토가 필요한 세션을 관리한다.
- 작업 완료 시 해당 세션의 대기 메시지가 두 개 이상이면 자동 dispatch를 중단하고 검토 상태로 전환한다.
- `continueQueuedMessages(sessionId)`를 통해서만 검토 상태를 해제하고 큐의 첫 항목을 실행한다.
- 실행 시 기존 배열에서 해당 첫 항목만 제거하므로 편집 여부와 관계없이 원래 FIFO 순서를 유지한다.
- 대기 항목이 하나뿐이면 기존처럼 자동으로 후속 작업을 시작한다.

### 사용자 인터페이스

- 각 큐 항목에 `편집`, `저장`, `취소`, `삭제` 동작을 제공한다.
- 인라인 textarea에서 `Enter`로 저장하고 `Shift+Enter`로 줄바꿈하며 `Escape`로 취소할 수 있다.
- 검토 상태에서는 안내 문구와 `편집 완료 후 진행` 버튼을 표시한다.
- 편집 중이거나 텍스트·첨부가 모두 없는 항목이 있으면 진행 버튼을 비활성화한다.

## 수용 조건

1. 실행 중 추가된 큐 메시지를 전송 전에 수정할 수 있다.
2. 현재 작업 완료 시 대기 메시지가 두 개 이상이면 다음 메시지가 자동 실행되지 않는다.
3. 사용자가 `편집 완료 후 진행`을 누르면 큐의 첫 메시지가 실행된다.
4. 수정된 메시지는 최초 큐에 들어간 순서를 유지한다.
5. 메시지가 하나만 대기 중이면 기존 자동 후속 실행 동작을 유지한다.
6. 큐 변경은 기존 localStorage 큐 저장소에 반영된다.
