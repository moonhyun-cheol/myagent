# 메모리 제안 / 모델 TODO 작성 주체 점검 및 반영 명세

## 범위와 상태
- 사용자 요청: 메모리 제안이 나오지 않는 이유와 To-Do의 임의 파싱 여부 확인.
- 이번 결과는 코어 정적 점검이다. 제품 코드 변경이나 메인앱 반영은 하지 않았다.
- 화면 To-Do의 데이터 공급 경로 및 실행 중 앱의 배포 버전은 검증하지 않았다. 따라서 화면의 임의 파싱 여부는 확정하지 않는다.

## 확인한 사실
1. `core/src/memory/user-memory-store.ts:49-53,207-222`: autoCapture는 기억해/메모해/remember this 등의 정규식으로 사용자 메시지를 검사한다. 모델 판단이 아니다. 일치하면 메시지를 최대 500자로 잘라 add로 직접 저장한다. projectId가 있으면 project, 없으면 global이며 session 범위는 자동 선택하지 않는다.
2. 같은 파일의 MemoryEntry에는 제안/승인/거절 상태가 없으며 source는 user/auto이다. formatForPrompt는 저장된 enabled 항목을 주입하는 기능이며 모델에게 새 메모리 후보를 제안하라고 안내하는 기능이 아니다.
3. `core/src/chat/chat-orchestrator.ts:1182-1189`: autoCaptureMemory는 저장 결과를 사용하지 않으며 예외를 삼킨다. 이 경로에는 제안 알림 반환이 없다.
4. `core/src/routes/dispatch.ts:1633-1683`: 확인한 /memory API는 조회/추가/수정/삭제다. 후보 제안 및 승인 상태 전환은 없다.
5. `core/src/agent/agent-tool-definitions.ts:95-146`, `agent-tool-execute.ts:273-286`: TODO 원장은 모델의 todo_update 호출 인자 todos/retainEvidence/workingNotes를 받아 병합 후 저장한다. 이 경로는 사용자 문장이나 최종 답변의 번호 목록을 파싱해 TODO를 생성하는 경로가 아니다.
6. `core/src/agent/agent-todo-ledger.ts`: normalizeTodo는 필드 길이 제한, 상태 기본값, 중복 근거 제거를 수행한다. mergeTodoLedgerUpdate는 같은 id를 갱신하고 누락 TODO를 보존한다. 이는 런타임의 정규화·병합이며 작업 의미를 새로 판단해 만드는 것은 아니다. 누락된 과거 TODO가 남을 가능성은 있다.

## 판정
- 메모리: 확인한 자동 저장 경로는 모델 기반 제안 기능이 아니다. 제안이 나오지 않는 현상과 구조적으로 일치한다. 전체 제품에 제안 기능이 전혀 없다고 검색만으로 단정하지 않는다.
- TODO: 코어 원장은 모델 작성 방식이다. 화면 To-Do가 같은 원장을 사용하는지는 별도 확인해야 한다.

## 메인앱 반영 요구사항 (미구현)
### 메모리
- 모델이 지속 가치 있는 선호/결정/프로젝트 규칙을 후보로 제안하는 명시적 도구를 제공한다.
- 후보에는 text, scope, reason, source session/message를 기록한다. 권한 있는 프로젝트/대화 범위는 서버에서 검증한다.
- pending 후보와 승인된 메모리를 분리하고 승인/수정 후 승인/거절을 지원한다. 미승인 후보는 상시 메모리로 주입하지 않는다.
- 문구 정규식 직접 저장을 모델의 의미 판단과 명시적 승인 정책으로 대체한다. 부정문·인용문·민감정보·중복·충돌을 다룬다.
### TODO
- 실제 화면 데이터 공급원을 추적해 todo_update 원장과 일치하는지 검증한다.
- 사용자 문장/모델 답변의 번호 목록이나 도구 실행 로그를 실제 TODO로 추론하는 fallback이 있다면 제거한다. 도구 실행 로그는 별도 표시한다.
- 모델이 작성하지 않았다면 빈 상태를 보여준다. 모델 작성 provenance를 UI와 저장 레코드에서 확인 가능하게 한다.
- 새 작업 전환 시 과거 TODO의 보존/종료/취소 정책을 명시한다. 현재 누락 항목 보존 정책을 무심코 전체 교체로 바꾸지 않는다.

## 반영 Acceptance
- 명시적 기억 문구 없이도 모델이 의미 있는 메모리를 제안할 수 있다.
- 승인 전 저장 메모리와 프롬프트가 바뀌지 않고 승인 후에만 올바른 범위에 반영된다.
- 부정문/인용문/비밀정보가 자동 저장되지 않으며 거절 후보가 반복 제안되지 않는다.
- 단순 번호 목록 입력만으로 TODO가 생성되지 않는다.
- todo_update 호출의 항목/상태가 실제 화면 및 재시작 후 원장과 일치한다.
- 도구 성공만으로 TODO가 임의 완료되지 않는다.

## 이번 검증 한계
문서 저장 검증은 구현 동작 테스트가 아니다. 브라우저 재현, 모델 실제 호출, 배포 앱 점검은 수행하지 않았다.
