# AI 요청의 402 오류 진단

402는 결제·비용 조건으로 요청이 거절됐다는 의미다. 상태 코드만으로 잔액 소진, 키 지출 한도, 요청 비용 초과 또는 최종 공급자 장애를 확정하지 않는다.

## 로컬 기록

실행 중인 앱의 데이터 루트 아래 `data/logs/llm-usage/llm-usage-YYYY-MM-DD.jsonl`을 확인한다. `MY_AGENT_LLM_USAGE_LOG_DIR`을 설정한 경우 그 경로를 사용한다. 개발 폴더와 설치본의 로그 위치는 다를 수 있다. 날짜는 UTC 기준이다.

- `start`: 요청의 대화·실행 ID, 모델, 연결 호스트(`endpoint_host`), 바이트 크기, 입력 항목 수, 최대 출력량을 기록한다. 최대 출력량은 API별 `max_output_tokens`, `max_completion_tokens`, `max_tokens`에 분리해 기록하며 미지정·유효하지 않은 값은 `null`이다. 이는 서버의 기본값이나 청구액을 뜻하지 않는다.
- `finish`: 각 HTTP 시도당 한 번 기록한다. HTTP 실패는 본문을 읽기 전에 기록하므로, 상세 사유는 아직 없을 수 있다.
- `http_error_detail`: 호출자가 오류 본문을 읽었을 때 같은 `call_id`로 추가한다. **실패 요청을 분석할 때 `finish`와 이 이벤트를 연결해서 본다.** 호출 횟수나 사용량에 더하지 않는다. 별도 백그라운드 본문 읽기는 하지 않는다.
- HTTP 200 스트림 안에서 공급자가 오류를 반환한 경우에는 `finish.error_diagnostics`에 사유를 기록한다.

## 사유 해석

`error_diagnostics.reason`은 공급자 문구·코드를 고정된 라벨로 분류한 진단 단서이며 잔액 조회 결과가 아니다.

| 값 | 의미 |
|---|---|
| `insufficient_credits` | 잔액·크레딧 부족을 알리는 문구가 있음 |
| `spending_limit` | 지출·사용 한도 관련 문구가 있음 |
| `request_cost_exceeds_balance` | 요청량·최대 토큰 대비 감당 가능한 비용이 부족하다는 문구가 있음 |
| `payment_required` | 결제 문제라는 일반 문구만 있음 |
| `payment_required_unspecified` | HTTP 402이지만 상세 사유를 구분할 정보가 없음 |
| `unspecified` | 그 외 분류되지 않은 오류 |

원래 코드·유형, 중첩된 공급자 코드·유형, 공급자 이름, 응답의 요청 ID도 형식이 허용되는 경우 기록한다. 공급자 이름은 응답에 있을 때만 알 수 있으며, 연결 호스트는 중간 게이트웨이일 수도 있다. 응답에 없는 공급자·잔액·한도는 추정해서 채우지 않는다.

## 성공·실패 비교 순서

1. 같은 `session_id`에서 실패 전후의 요청을 찾고 `call_id`별 이벤트를 묶는다.
2. `endpoint_host`, `provider_id`, `model`, 최대 출력량, `request_bytes`를 비교한다.
3. 오류 코드·사유·공급자 이름·요청 ID를 확인한다. 상세 이벤트가 없거나 `error_observation`이 `invalid_json`, `truncated`, `read_error`, `cancelled`이면 본문 진단이 제한된 상태다.
4. 성공 요청의 입력·캐시 토큰을 대조한다. 실패 요청의 토큰 값이 없으면 0으로 간주하지 않는다. 바이트 수는 토큰 수나 비용과 같지 않다.

## 안전·범위

질문·답변·원문 오류 문구·임의 메타데이터는 저장하지 않는다. 오류 본문 관찰은 최대 32,768문자로 제한하며, 응답 본문은 호출자에게 그대로 전달한다. URL은 호스트만 기록하고 인증정보·경로·쿼리를 기록하지 않는다. 이 변경은 기존 선택형 wire 로그의 정책을 바꾸지 않는다. 로컬 로그의 호스트·식별자도 내부 정보일 수 있으므로 외부 공유 시 검토한다.

`MY_AGENT_LLM_USAGE_LOG=off`이면 사용량·오류 상세 로깅을 끈다. 디스크 쓰기 실패는 AI 요청을 중단시키지 않는다. 이 변경은 캐시 정책, 모델, 최대 출력 설정, 재시도 정책을 바꾸지 않으며 기존 로그에 없던 정보를 소급 복구하지도 않는다.
