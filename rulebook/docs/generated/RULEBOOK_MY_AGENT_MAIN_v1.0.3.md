## 시스템 경계

MY Agent는 Windows 데스크톱 제품이다. 사용자 관찰 표면은 다음 세 프로세스다.

1. **WPF 셸** (`shell/CqrPa.Shell` → `MYAgent.exe`) — 커스텀 타이틀 크롬, WebView2 호스트, Node API 기동/종료.
2. **Node API** (`core/src/main.ts` → `core/dist/main.js`) — HTTP 라우터, 채팅/에이전트, 라이선스, 세션, FS.
3. **React 워크스페이스 UI** (`ui/workspace`) — 제품 UI의 유일한 화면. 프로덕션에서는 API가 `ui/workspace/dist`를 `/`로 서빙한다.

시스템 밖(외부 관찰자):

- LLM 제공자 (OpenRouter / Open WebUI / 사용자 정의 OpenAI-compatible / 조건부 Ollama)
- 활성화 서버 (`activation-server`, 배포 설정 URL)
- 업데이트 피드 (`https://raw.githubusercontent.com/moonhyun-cheol/myagent/main/channels/stable.json`) — 코어
- 조직 모듈 피드 (`module.json` `update_feed_url`, raw.githubusercontent.com) — 코어와 별 시퀀스
- 선택 MCP/Playwright/OpenClaw(Automaton)

# 02. ALWAYS-ON RULES (P0)

재구현·룰 작업에서 항상 적용. 위반 시 동등 시스템으로 보지 않는다.

1. **단일 UI.** 제품 화면은 `ui/workspace`. `/legacy`, `/ui` 는 404.
2. **localhost API.** `127.0.0.1` + 기본 포트 10200.
3. **세션 헤더.** 클라이언트 `X-CQR-Session`, 서버 `x-cqr-session`, 기본 `"default"`, 최대 64자.
4. **권위.** 라이브 분기가 명세다. `AGENTS.md`와 주석은 2026-08-27 캡처에서 라이브와 맞춰 두었다. 다시 어긋나면 라이브 코드를 따른다. (ADR-RE-002)
5. **에이전트 진입.** `sessionRoot || (scope === 'standalone' && hasDevWorkspace(configPath))`. `mode`/`message`로 재판정 금지. 전역 `dev_workspace_root`가 있으면 최상위 새 채팅도 에이전트다.
6. **단일 코더.** 한 턴의 역할은 `coder` 하나다. planner/reviewer 체인을 돌리지 않는다.
7. **완료.** 모델이 도구 없이 산문으로 멈추면 완료다. 라이브에서 `evaluateOutcomeGate`로 답을 재작성하지 않는다. 로컬은 silent verify·`ERROR: SYNTAX_BROKEN`·Exit Gate 노트만 집행한다.
8. **변이 UI.** `MutateReviewPane.tsx` 없음. 워크스페이스에 변경 Accept/Reject 패널을 띄우지 않는다. 롤백은 체크포인트 API다.
9. **실패 평면.** 도구 평면 실패 → 일반 채팅 강등 금지.
10. **라이선스.** `read_only` 에서 쓰기 API 403.
11. **확인 대화상자.** `window.confirm` 금지. `ConfirmModal`/`confirmDialog`.
12. **제목 표시줄 ≠ ChatPane.** 셸 `MainWindow.xaml` vs `ChatPane.tsx`.
13. **계약 PASS.** 실행 증거 없는 `PASS` 금지. 이 룰북 계약은 전부 `UNVERIFIED`.
14. **시크릿.** vault 키·토큰을 명세 예시에 실값으로 넣지 말 것.
15. **인앱 브라우저.** 「연결됨」 주장은 `postMessage inAppBrowser.open` 또는 `NavigationStarting`→`OpenInAppBrowser` 경로가 있을 때만.
16. **모델 지시 런타임.** 도구 선택은 모델, 로컬은 스키마·승인·경로·증거.
17. **버전 vs 시퀀스.** 공개 이름은 `MY Agent {version} (update {N})`. 클라이언트는 `update_sequence`만 따른다. SemVer는 사용자 의미가 바뀔 때만 올린다. (ADR-RE-003)
18. **업데이트 두 갈래.** 코어는 Yes → 진행 창 → Updater → 셸 재시작. 조직 모듈은 기동 백그라운드에서 폴더만 교체하고 재시작하지 않는다. (ADR-RE-004)

# 1. 시스템 개요 및 아키텍처

- **Rule IDs:** R-101, R-102, R-103
- **소스 revision:** git `468456fff03e3a2836730dc9499af8bbada3cf04` + 미커밋 작업 트리 (제품 1.0.3 / seq 8)
- **근거 파일:** `manifest.json`, `shell/CqrPa.Shell/*`, `core/src/main.ts`, `core/src/api-server.ts`, `core/src/routes/dispatch.ts`, `ui/workspace/src/main.tsx`

## 1.1 전체 목적

MY Agent는 로컬 Windows 머신에서 동작하는 코딩 에이전트 데스크톱이다.

| 목적 | 관찰 가능한 결과 |
|------|------------------|
| 채팅 | `POST /chat` JSON 또는 `POST /chat/stream` SSE로 assistant 텍스트가 세션에 저장된다 |
| 워크스페이스 코딩 | 세션이 작업 폴더에 묶이면 도구로 디스크를 읽고 쓰며, `data/agent-run-meta/<session>.json`에 경로가 남는다 |
| 라이선스 | `data/vault/license.ocx`가 없거나 무효이면 `license.mode = read_only`이고 쓰기 API는 403 |
| 단일 UI | `GET /` 은 `ui/workspace/dist` SPA. `/legacy`, `/ui` 는 404 |

핵심 메커니즘: **모델이 도구 사용을 결정**하고, **로컬 런타임은 도구 스키마·승인·경로 보안·구문/진단 증거만 집행**한다. 요청 문구 정규식으로 작업 모드를 재판정하지 않는다 (`shouldRunWorkspaceAgent`가 `mode`/`message`를 void).

## 1.2 프로세스 토폴로지

```

  └─ MYAgent.exe                    [WPF, shell/CqrPa.Shell]
        ├─ ApiProcessHost.Start()
        │     spawn runtime/node/node.exe core/dist/main.js
        │     env: MY_AGENT_ROOT, CQR_API_PORT=10200
        │     bind: 127.0.0.1:10200
        └─ MainWindow WebView2
              Navigate http://127.0.0.1:10200/
                    └─ Node API serve ui/workspace/dist
                          └─ fetch('/chat/stream')  (same origin)
```

### 1.2.1 기동 순서 (실패 시 분기 포함)

| 단계 | 행위자 | 함수/이벤트 | 성공 | 실패 |
|------|--------|-------------|------|------|
| 1 | WPF | `App.OnStartup` | `CqrPaths.ResolveCqrRoot()` | 루트에 `manifest.json` 없거나 `MY_AGENT_ROOT` 무효 |
| 2 | WPF | `ApiProcessHost.Start()` | `GET /health` 가 제한 시간 내 `ok` | MessageBox `"API 시작 실패..."` 후 `Shutdown(1)` |
| 3 | Node | `main.ts` → `startApiServer(port)` | `listen(127.0.0.1, port)` | 프로세스 종료, 셸 헬스 타임아웃 |
| 4 | Node | `createApiServer` | `ensureDataDirs`, stores 구성 | 디렉터리 생성 실패 시 throw |
| 5 | WPF | `LoadWorkspaceAsync` | WebView2 `Navigate` | `"로컬 서비스가 제한 시간 안에 준비되지 않았습니다."` + 재시도 버튼 |
| 6 | 종료 | `App.OnExit` | 셸이 기동한 Node 프로세스 트리 종료 | — |

헬스 대기: 기본 **60초**, 버전 불일치 재시작 후 **90초**. 프로브 타임아웃 **2초**, 주기 **200ms**. 포트 10200의 stale Node는 dist mtime 또는 manifest version 불일치 시 종료 후 재기동.

## 1.4 데이터 흐름

### 1.4.1 채팅 한 턴 (워크스페이스 바인딩 있음)

```
1. UI sendAiMessage
     LiveJob + AbortController
     같은 sessionId 가 이미 실행 중이면 FIFO 큐
2. POST /chat/stream
     Header X-CQR-Session: <sessionId>
     Body ChatRequest
3. dispatch: license.assertWritable + feature(chat 또는 web_dev)
4. orchestrator
     inlet filter → resolveRouting → shouldRunWorkspaceAgent == true
```

게이트 TRUE인 경우(세션 폴더 **또는** standalone+`dev_workspace_root`)는 1.4.1.

## 1.7 재구현자가 바꾸면 안 되는 아키텍처 불변조건

1. API는 `127.0.0.1`에만 바인딩한다.
2. 기본 포트는 10200이며 `CQR_API_PORT`로만 덮어쓴다.
3. 제품 UI는 `ui/workspace` 하나다. `/legacy`, `/ui` 는 제거된 경로로 404.
4. HTTP는 단일 디스패처 `dispatchApiRequest`로 진입한다.
5. 워크스페이스 에이전트 진입은 `sessionRoot || (standalone && hasDevWorkspace)` 만으로 결정한다. 메시지 키워드로 재판정하지 않는다. 전역 `dev_workspace_root`가 있으면 최상위 새 채팅도 에이전트다.
6. 도구 평면 실패를 일반 채팅으로 강등하지 않는다 (ADR-008).
7. 한 턴의 MAR 역할은 `coder` 하나다. planner/reviewer를 직렬 실행하지 않는다.
8. 라이브 완료는 모델 산문 정지다. `evaluateOutcomeGate`를 에이전트 루프에서 호출하지 않는다.
9. 워크스페이스 UI에 변이 Accept/Reject 패널을 두지 않는다. `MutateReviewPane.tsx`는 존재하지 않는다.

## 3.1 라우팅

### Pre-conditions

- HTTP 본문이 `ChatRequest`로 파싱됨
- 라이선스 쓰기 + feature `chat` (모드별 추가 feature는 4부)

### 알고리즘 `resolveRouting`

```
1. inlet filter가 메시지를 차단하면
     return { mode: 'chat', layer: 'bypass' }
2. req.mode 가 있으면
     return { mode: req.mode, layer: 'explicit' }
3. message 가 '/' 로 시작하고 peekAutomatonIntent(message) 가 매칭되면
     return { mode: 'automaton_direct', layer: ... }
4. return { mode: 'chat', layer: 'default' }
5. 이후 handle/handleStream에서:
     if routing.mode == 'web_dev' AND NOT shouldRunWorkspaceAgent(...)
       routing.mode = 'chat'
```

**금지:** UI “코드 모드” 키워드/정규식으로 agent 평면을 고르지 않는다.

### `shouldRunWorkspaceAgent` (정확 조건)

입력: `configPath`, `sessionStore`, `projectStore`, `sessionId`.  
`mode`, `message`, `explicitMode`는 **무시** (void).

```
sessionRoot = resolveWorkspaceRootForSession(sessionStore, projectStore, sessionId)
scope = resolveSessionContextScope(...)
return Boolean(sessionRoot || (scope == 'standalone' && hasDevWorkspace(configPath)))
```

| 세션 | 결과 |
|------|------|
| `workspace_project_id`가 가리키는 폴더가 존재 | TRUE (agent) |
| standalone (최상위 새 채팅 포함) + `dev_workspace_root` 설정됨 | TRUE (agent) |
| 폴더 바인딩 없음 + 전역 워크스페이스 없음 | FALSE (plain chat) |

소스 파일 주석이 「새 채팅은 노트북 폴더를 상속하지 말 것」이라고 해도 **라이브 식은 위 표가 전부**다. 주석은 무시한다.

TRUE이면 `runWorkspaceCodeAgent` → `promoteWorkspaceAgentRouting`: `mode==='chat'`일 때만 `web_dev`로 승격.

### Structured mode 우선순위 (agent 게이트 이전)

1. `automaton_direct`
2. `deep_research`
3. `image_gen`
4. `browser_automation`
5. `browser_agent`
6. `web_crawl`

## 3.3 Code agent 메인 루프

### Pre (`runCodeAgentInner`)

| 검사 | 실패 |
|------|------|
| `assertDevWorkspaceRootReadable(workspaceRoot)` | throw / 오케스트레이터 POLICY_REFUSAL |
| `providerStore.resolveProvider` | PROVIDER_NOT_CONFIGURED 등 |
| `isCodeAgentLlmProvider` | 코딩 제공자 아님. Ollama는 `MY_AGENT_ALLOW_OLLAMA_CODE=1` 또는 `local_only`만 |
| `getCodeAgentToolsByPackAsync` | pack `files` 또는 `files+browser` |
| harness / OWUI protocol | `loadHarnessPolicy`, `resolveCodeOwuiProtocolMode` |

Ollama 비상 폴백: `runCodeAgent` catch에서 `ollamaEmergencyFallbackEnabled` 이고 gateway 에러면 provider `ollama`로 1회 재시도. 기본 `MY_AGENT_OLLAMA_FALLBACK` off.

### Setup (루프 전)

```
hooks = merge(default, audit ledger, caller)
messages = buildAgentMessages(system, tools, workspace snapshot, product memory, ui-facts if self-workspace)
meta = loadAgentRunMeta(cqrRoot, sessionId)
if openGateBlocksDoneClaim(meta.openGate): inject formatOpenGateSystemNote
if shouldOrInContinuityAutopilot: autopilot=true; maxSteps = min(30+15, 60)
inject: autopilot note, activeTask, task ledger, session continuity, lockedConstraints
seed WorkspaceReadGate from session read/mutate paths if continuity
hooks.beforeRun → stop이면 finish
```

### Step loop (`runAgentStepLoopInner`)

상수: `MAX_AGENT_STEPS = 30`, `AGENT_STEP_TIMEOUT_MS = 600_000`.

```
WHILE steps < maxSteps:
  throwIfAborted
  steps += 1
  hooks.beforeModel → stop이면 finish
  LLM:
    protocol==client → completeAgentStepClientProtocol  (TEXT TOOL_CALL:)
    protocol==api    → completeAgentStep + chatCompletionWithTools(toolChoice:'auto')
    OWUI/gateway 실패 → shrinkMessagesForInfraRetry, 같은 step 재시도
    native 실패 and not nativeToolsLocked → sticky TEXT rememberClientToolProtocol

  IF no tool_calls:
    sanitize "Tool not found" poison
    IF empty → completeAgentAnswerStep 재시도
    IF mutatedOkRun AND evidenceDiagOk==null → silent runWorkspaceDiagnostics
    RETURN finish({ content: text })

  FOR each tool_call:
    loopGuard → soft 교정 or hard stop
    applyToolSchemaCompat
    duplicate read_file same path this run → ALREADY_READ, skip
    needsHumanApproval → §3.4
    WorkspaceReadGate.assertCanMutate → 실패 시 list_directory+read_file auto-heal 최대 2
    first mutate → createWorkspaceCheckpoint
    hooks.beforeTool
    output = executeAgentTool(...)
    post-mutate syntax gate + wiring smoke 를 tool output에 append
    persistLiveSessionMeta
    onWorkspaceMutate(paths)
    push truncated tool result (MY_AGENT_TOOL_RESULT_MAX_CHARS)

  IF loop hard stop: finish(guard)
  IF SYNTAX_BROKEN and retries left: repair prompt, continue
  IF mutate this step and silent verify retries left:
    diagnostics (+ optional tests)
    fail → repair user message, continue
    pass → record verify witness

THROW "Code agent exceeded N tool steps"
```

### `finish` post-conditions

- `appendSessionMutatedPaths` / `appendSessionReadPaths` (`skipSessionMetaAppend`가 아니면)
- `scrubAgentChannelLeak`
- `recordSessionPerf` + `data/logs/agent-perf.jsonl`
- audit `run_end`
- `CodeAgentResult` 반환
- finally: `cancelTerminalJob`, browser session close

### 중단

catch에서 미완료이면 `persistInterruptedAgentProgress` (경로 + interrupt openGate).  
오케스트레이터는 infra retry (`MY_AGENT_TOOL_PLANE_INFRA_RETRIES`) 및 auto-resume (`MY_AGENT_TOOL_PLANE_AUTO_RESUME`) 후, 실패 시 `formatToolPlaneFailureAssistant`. **chat으로 강등 금지**.

## 3.6 완료와 Exit Gate (라이브)

완료 신호: 모델이 해당 스텝에서 `tool_calls` 없이 산문을 반환하면 `finish({ content })`. 로컬은 그 답을 false-completion으로 재작성하지 않는다.

라이브에서 로컬이 하는 일:

1. mutate 뒤 silent `runWorkspaceDiagnostics` (+ 선택 tests) → 실패 시 수리 프롬프트로 루프 계속
2. post-mutate 구문 게이트 → `ERROR: SYNTAX_BROKEN` 이면 수리 루프
3. 세션 `openGate`가 열려 있으면 다음 턴 시스템 노트(「이 게이트만 닫을 것」). `openGateLikelyAddressed` 휴리스틱으로 닫을 수 있음

`evaluateOutcomeGate()`는 **제품 런타임이 아니다.** `tools/verify-*.mjs`만 호출한다. 재구현 시 에이전트 루프에 넣지 않는다. 함수 내부 reason 표는 오프라인 검증기 설명일 뿐 사용자 관찰 계약이 아니다.

Critic이 `clearSessionOpenGate`를 호출하는 경로는 역할이 `reviewer`일 때만 있다. 라이브 `planMarRoles`는 reviewer를 넣지 않으므로 그 경로는 타지 않는다. Exit Gate는 continuity/interrupt/수동 소스 등으로만 열린다.

## 3.7 Reasoning / Autopilot (로컬 vs 모델)

| 항목 | 결정 주체 | 로컬 집행 |
|------|-----------|-----------|
| 도구 호출 여부 | 모델 (`toolChoice: auto`) | 스키마 제공, 프로토콜 수송 |
| 작업 모드 키워드 | 사용 안 함 | `sessionRoot` 또는 standalone+`dev_workspace_root` |
| reasoning effort | 세션 `execution_policy.reasoning` | `MY_AGENT_REASONING_EFFORT`가 있으면 항상 우선. `*pro*` 모델은 명시 override 없으면 omit. qwen2.5/llama3 등은 reject 시 omit |
| 메시지 문구로 reasoning 낮춤 | **금지** | — |
| autopilot | `execution_policy.autopilot` + env | ON이면 시스템 노트 “이번 런에서 끝”, maxSteps +15 cap 60. 열린 Exit Gate/연속성은 `MY_AGENT_CODE_AUTOPILOT` 기본 on으로 OR-in (`shouldOrInContinuityAutopilot`). 하드 off는 제외 |
| OWUI 프로토콜 | env | 코드 기본 `MY_AGENT_CODE_OWUI_PROTOCOL=api`. `MY_AGENT_OWUI_TEXT_TOOLS=1`이면 TEXT. native 실패 후 provider/model 키에 sticky TEXT |
| Ollama 코딩 | env | 기본 off |

## 3.8 에이전트 역할 (MAR 래퍼)

`runMarOrCodeAgent`: `MY_AGENT_MULTI_AGENT=0`이면 `runCodeAgent`만 호출. `1`(기본)이어도 `planMarRoles()`는 항상 다음을 반환한다.

```
{ roles: ['coder'], reason: 'model_directed_single_agent', toolPack: files 또는 files+browser }
```

`_message`와 opts의 플래그는 void. planner/browser/researcher/reviewer를 붙이지 않는다.

한 턴 = 단일 `runCodeAgent`. `appendRoleContribution`은 coder 한 줄일 수 있다.  
`MY_AGENT_MANDATORY_CRITIC`는 reviewer가 플랜에 없을 때 **효과가 없다.** 재구현자가 reviewer를 넣으면 이 룰북과 다른 제품이다.

## 5.3 복구 / 롤백 / Fallback

### 워크스페이스 체크포인트

- **생성:** 에이전트 런에서 **첫 mutate 직전** `createWorkspaceCheckpoint`.
- **위치:** `data/agent-checkpoints/<sessionKey>/<id>/`
- **한계:** 파일 400개, 파일당 2MB. `node_modules`, `.git`, `data` 등 스킵.
- **GC:** `MY_AGENT_CHECKPOINT_MAX_AGE_DAYS` 기본 7, `KEEP` 기본 5, `MAX_MB` 기본 200.
- **롤백:** `POST /workspace/checkpoint/rollback` + `confirm: true`. 부분 `paths` 가능. 세션 undo와 별개.
- **UI:** `MutateReviewPane.tsx`는 삭제됨. store에 `pendingMutateReview` 없음. 변이 후 Accept/Reject 화면을 띄우지 않는다. 파일 변경은 즉시 디스크에 남는다. 롤백은 `POST /workspace/checkpoint/rollback`만. 재구현 시 수락 화면을 추가하면 이 룰북과 다르다.

### 도구 평면 실패

- infra LLM 실패: 축소 메시지 재시도 → 프로토콜 TEXT 폴백(잠금 아니면) → 오케스트레이터 retry/auto-resume.
- 최종 실패: assistant 실패 버블. **plain chat 재실행 금지**.
- Ollama emergency fallback: env opt-in + gateway 에러 시에만 `runCodeAgent` 래퍼.

### 라이선스

복구: `POST /setup/import-license` 또는 `POST /setup/activate` 또는 셸 `--import-license` (NAS 경로 금지). 성공 시 gate reload → `full`.

### 업데이트 설치

`TransactionalInstaller`: 실패 시 이전 트리 롤백. 서명/해시 실패는 설치하지 않음. 네트워크 타임아웃은 기존 설치 유지(silent continue).

### 터미널

`POST /fs/run-terminal/cancel` → `cancelled: true`. job 목록 GET.

### 세션 undo

`POST /sessions/:id/undo` → 마지막 턴 pop. 없으면 `NOTHING_TO_UNDO`. 디스크 파일 mutate는 되돌리지 않음 (체크포인트와 별개).

## 5.4 실패 평면 불변조건 (ADR-008)

1. 인프라 오류를 모델 답변처럼 병합하지 않는다 (`AgentInfraError`).
2. 에이전트 경로 throw는 상위로 전파한다. 라이브 역할은 coder 하나이므로 planner throw 경로는 없다.
3. UI는 `web_dev` 스트림 오류를 일반 채팅으로 강등하지 않는다.
4. 워크스페이스 없이 mutate 시도 → policy refuse 문구, 도구 실행 없음.

## 5.5 에러 리포트

설정 `error_report.enabled`. 수동 `POST /error-report/send`, 테스트 `POST /config/error-report/test`. 자동 루프는 api-server 기동 시. 민감 경로/시크릿을 리포트에 넣지 않는 것은 지원 서비스 구현을 따른다 (재구현 시 redaction 필수).

# ADR-RE-001 — 외부 역공학 룰북 워크스페이스

- 상태: accepted

## 결정

MY Agent의 **재구현용 기술 룰북**은 소스 트리 `rulebook/docs`가 아니라 `C:\MY_FULL_AI\RULEBOOK\MY_CUSTOM_CODEX`에 둔다.

## 이유

1. 사용자 지정 경로가 소스 밖 Rulebook Workspace다.
2. 소스 `rulebook/docs/generated/RULEBOOK_MY_AGENT_MAIN_v1.0.1.md`는 스텁이다.

## 결과

- 권위 원본: 이 디렉터리의 `docs/specs/technical/01`–`06` + `rulebook.yml`.
- `contracts/`는 관찰 가능 IPO. `verification_status`는 증거 전까지 `UNVERIFIED`.
- `policy.implementation_agnostic: false` — 이 룰북은 모듈·의사코드·에러 코드를 고정한다. v2 스킬의 순수 재현 계약만으로는 사용자 프롬프트(역공학)를 충족하지 못함.
- 소스 루트 `.rulebook-link.yml`이 이 매니페스트를 가리킨다.

## 비범위

라이선스 개인키, 제공자 API 키, 활성화 토큰은 기록하지 않는다.

# ADR-RE-002 — 룰북 권위는 실작동 분기

- 상태: accepted
- 날짜: 2026-08-27
- 소스 revision: `c5eb3a2c53d5575e785cff76e6663efc26d32723`

## 결정

이 룰북의 규범은 **실행 경로가 실제로 타는 분기**다. `AGENTS.md`와 라이브 주석은 `cd7c3b7`에서 그 분기에 맞춰 두었다. 다시 어긋나면 라이브 코드를 따른다.

충돌 시 우선순위:

1. 라이브 호출 그래프 (`handleStream` → `shouldRunWorkspaceAgent` → `planMarRoles` → `runAgentStepLoop`)
2. 사용자/클라이언트가 관찰하는 HTTP·SSE·디스크·화면
3. verify 스크립트 전용 헬퍼 (`evaluateOutcomeGate` 등) — 제품 동작 계약 밖
4. 어긋난 주석 / 구형 메모리 문서 / 데드 코드 — 무시

## 실작동으로 고정한 네 규칙

1. **MAR:** `planMarRoles()` / `runMultiAgent`는 항상 `roles: ['coder']`. planner/reviewer 체인을 돌리지 않는다.
2. **완료:** 라이브 루프는 `evaluateOutcomeGate()`를 호출하지 않는다. 모델이 도구 없이 산문으로 멈추면 그 답이 완료다. 로컬은 silent verify·구문 게이트·Exit Gate 노트만 집행한다.
3. **변이 리뷰 UI:** `MutateReviewPane.tsx` 삭제. store에 `pendingMutateReview` 없음. 롤백은 `POST /workspace/checkpoint/rollback` API만.
4. **에이전트 진입:** `sessionRoot || (scope === 'standalone' && hasDevWorkspace(configPath))`. 전역 `dev_workspace_root`가 있으면 최상위 새 채팅도 에이전트 평면이다.

## 결과

재구현은 위 네 규칙을 복제해야 동등하다. planner/Critic 체인, 라이브 outcome-gate 재작성, 변이 수락 UI를 구현하면 **이 룰북과 다른 제품**이 된다.

## 후속 (2026-08-27)

소스에서 미사용 `MutateReviewPane`을 제거하고 `AGENTS.md`·MAR/워크스페이스 주석을 라이브와 동기화했다 (`cd7c3b7`).

- 소스 revision: 작업 트리 제품 `1.0.3` / seq 8 (git HEAD `468456f` + 미커밋)

## 결정

기계가 “더 새 패키지인가”를 판정하는 값은 **`update_sequence`** 다. SemVer `version`은 사람에게 제품 의미를 말할 때만 올린다. 공개 이름은 항상 둘을 붙인다.

```text
MY Agent {version} (update {N})
```

설치 zip 태그(`v{version}`)는 시퀀스 패키지가 아니다. 공개 이름은 `MY Agent {version} (install)` 이다.

## 올리는 근거

| 무엇을 | 언제 | 관찰 결과 |
|--------|------|-----------|
| `update_sequence` +1 | 서명된 클라이언트 zip을 새로 배포할 때마다 | 피드·payload·`manifest.json`의 시퀀스가 커진다. 재사용·롤백 금지 |
| patch `x.y.Z` | 사용자가 체감하는 수정·보안·동작 변화 | `version` 문자열이 바뀐다. 시퀀스도 +1 |
| minor `x.Y.0` | 새 사용자 기능 | 동일 |
| major `X.0.0` | 호환 파괴, 재설치, 또는 `minimum_supported_sequence` 상향 | 동일 |
| SemVer 유지 | 미사용 코드 삭제, 에이전트 메모리 정렬, 릴리스 제목만 고친 경우 | 버전 문자열은 같고 시퀀스만 +1. seq 8 / 1.0.3 이 칸 (진행 창은 사용자 체감이지만 버전 문자열은 유지됨) |

## 라이브 경로

- 업데이터는 피드의 `update_sequence`만 비교한다. SemVer 파싱 없음 (`UpdateService.cs`, `verify-beta-release.mjs`).
- GitHub 시큐어 업데이트 제목은 `formatGitHubReleaseTitle` → `MY Agent {version} (update {N})`.
- 채널 피드 `channels/{stable\|beta}.json`의 `document.version`과 `document.update_sequence`가 이 정책의 관찰 출력이다.

## 결과 동등성

두 배포가 같으려면 공개 이름·피드 시퀀스·zip sha256이 같아야 한다. 버전 글자만 같고 시퀀스가 다르면 다른 패키지다.

# ADR-RE-004 — 코어 업데이트와 조직 모듈 업데이트는 다른 관찰 결과

- 상태: accepted
- 날짜: 2026-08-28
- 소스: 작업 트리 `MY Agent 1.0.3 (update 8)` (`UpdateService.cs`, `App.xaml.cs`, `organization-module-feed.ts`)

## 결정

서명된 배포는 **두 갈래**다. 같은 확인창·같은 재시작을 공유하지 않는다.

| 갈래 | 누가 | 사용자 관찰 | 프로세스 |
|------|------|-------------|----------|
| 코어 | WPF `UpdateService` + `MYAgent.Updater.exe` | 시작 후 Yes/No. **예**면 진행 창, zip 다운로드, 업데이터 콘솔, **셸 종료 후 `MYAgent.exe` 재시작** | 피드 `channels/stable.json`, `update_sequence` |
| 조직 모듈 | Node `maybeApplyOrganizationModuleOnLaunch` | 확인창 없음. `modules/organization`만 교체 | 설치된 `module.json`의 `update_feed_url` (raw.githubusercontent.com). **재시작 없음** |

`MY_AGENT_UPDATE_CHECK=0`이면 두 갈래 모두 생략한다.

## 코어 Yes 경로 (라이브)

1. 트레이면 창을 다시 올린 뒤 Yes/No.
2. **예** → `UpdateProgressWindow` (받은 바이트/%, 취소 가능).
3. 피드 GET은 20초 제한. zip은 `HttpClient.Timeout = InfiniteTimeSpan`. 실패는 MessageBox (타임아웃/네트워크/서명).
4. `LaunchUpdater` (`CreateNoWindow = false`) 후 `Shutdown(0)`. 업데이터가 parent pid 종료를 기다렸다가 파일을 바꾸고 exe를 다시 켠다.

10초 전역 HTTP 타임아웃으로 zip을 받던 동작은 이 캡처에서 폐기한다. 그 동작은 Yes 이후 화면이 그대로인 실패와 동등하다.

## 조직 모듈 기동 경로 (라이브)

1. API 기동 후 `licensed: mode===full && chat`이면 `check` → 더 새 seq면 `apply`.
2. 전체 **15초** `AbortSignal.timeout`. 초과 시 `api-start.log`에 `skip MODULE_UPDATE_TIMEOUT`.
3. `MYAgent.exe` / Node를 끄지 않는다. 설정 → 스킬 → **업데이트 확인**은 같은 피드를 수동으로 본다.

## 결과 동등성

코어 업데이트가 창을 재시작하지 않거나, 조직 모듈이 Updater/Shutdown을 타면 동등 시스템이 아니다.

# Global reproduction constraints

Observer: HTTP client on `127.0.0.1:{CQR_API_PORT|10200}` and/or WebView2 user.

Always:

- Bind loopback only.
- Do not expose vault secrets or absolute machine paths in JSON error `message` when avoidable; never echo API keys.
- License `read_only` blocks writes with HTTP 403 before mutation.
- Workspace agent dispatch ignores chat message text. TRUE when sessionRoot is set OR (standalone AND hasDevWorkspace). Top-level new chat with a PC-wide dev_workspace_root uses the agent plane.
- One agent role per turn: coder only. Do not run planner/reviewer.
- Model prose with no tool_calls is completion. Do not call evaluateOutcomeGate in the live loop.
- Workspace UI does not show mutate Accept/Reject. Checkpoint rollback is API-only.
- Tool-plane failure must not be rewritten as a successful plain-chat completion.

Nondeterminism: LLM token text is not an exact oracle. Compare HTTP status, JSON schema, SSE `type` sequence categories, session message counts, and disk side effects.
